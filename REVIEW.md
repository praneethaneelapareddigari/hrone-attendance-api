# REVIEW.md

Review of the starter `app/main.py`. Shift 09:30-18:30 unless stated. "Fixed in" names the function in the final file.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | Module top, `MongoClient(...)` | No `tz_aware=True`, so PyMongo returns **naive** datetimes. Those can't be compared with IST-aware datetimes, and their zone depends on how they were made. | Comparing a stored `punch_in` with an aware shift time raises `TypeError: can't subtract offset-naive and offset-aware datetimes` → 500. | `MongoClient(..., tz_aware=True)`; every datetime in the code is aware (UTC or IST). |
| 2 | Module top, `os.getenv(..., "mongodb://localhost:27017")` / `"attendance_db"` | Connection details are hard-coded as fallbacks. If the grader's variable is missing, the app silently talks to the wrong DB. | Unset `MONGO_URI`: the app starts and reads an empty local DB instead of failing. | Read both from the environment (`.env` only as a fallback, real env wins); fail fast if missing. |
| 3 | `compute_late_minutes` | Grace check uses truncated *minutes* (`int(...) > 10`), so anything up to 10:59 after shift start counts as on time. | R2 example: 09:40:01 must give **10**; the starter gives **0** (also 09:40:59 → 0). | Compare whole **seconds** `> 600`, then `seconds // 60` (`late_minutes`). |
| 4 | `compute_late_minutes` | `punch_in.replace(hour=h, minute=m)` builds the shift start in whatever zone/date `punch_in` has (UTC or server-local), not IST on the attendance date. Overnight shifts use the wrong day. | On a UTC server, a punch at 09:45 IST (04:15 UTC) is compared with 09:30 UTC → 0 late instead of 15. A 05:30 punch for a 22:00 shift is compared with 22:00 the same day. | `shift_start_at(day, emp)` builds the shift start from the attendance date in IST. |
| 5 | `compute_work_hours` | Uses `round()`, which is float/banker's rounding, not half-up (R4). | 09:00:00 → 12:00:18 is exactly 3.005 h; `round(3.005, 2)` = **3.0**, contract says **3.01**. | `Decimal(seconds) / 3600` quantised with `ROUND_HALF_UP` (`work_hours`). |
| 6 | `compute_overtime` | No 30-minute minimum (R3); returns any positive number. | DATA_MODEL sample 1: out 18:35 → must be 0, starter gives 5. | `overtime_minutes` returns the value only if `>= 30`. |
| 7 | `compute_overtime` | Shift end always on `date_str`; for an overnight shift it must be the next day. | Sample 7 (22:00-06:00, out 06:40 next day): starter gives 1480 min instead of 40. | `shift_end_at` adds a day when `shift_end <= shift_start`. |
| 8 | All helpers | Instants are never truncated to whole seconds before calculations (R1). | punch at 09:40:00.900: stored/returned with .900 ms instead of 09:40:00. | `ms_to_dt` does `ms // 1000`; `truncate_seconds` before every calculation. |
| 9 | `EmployeeIn` | No validation at all: `emp_code` pattern, email, `HH:MM`, `joined_on` date, `shift_start != shift_end`. | `{"emp_code": "x", "joined_on": "yesterday"}` → 201 instead of 422. | `EmployeeCreate` with `Field` patterns/lengths, date validator, model validator for equal shifts. |
| 10 | `create_employee` | Check-then-insert (`find_one` then `insert_one`) and no unique index: two concurrent creates both pass the check. | Fire 8 identical POSTs in parallel → several 201s and duplicate `emp_code`s. | Unique index on `emp_code`; just insert and map `DuplicateKeyError` → 409. |
| 11 | `create_employee` | `created_at = datetime.now()` is naive server-local time and is returned as an ISO string, not epoch ms. | Response shows `"created_at": "2026-10-15T12:00:00"` instead of an integer. | Aware UTC time stored as BSON date, returned via `dt_to_ms`. |
| 12 | `list_employees` | `skip = page * page_size` skips the whole first page. | `page=1` with 3 employees returns `[]`. | `skip((page - 1) * page_size)`. |
| 13 | `list_employees` | `total` counts the whole collection, ignoring the department filter; no sort by `emp_code`; `page`/`page_size` not bounded. | `?department=Sales` returns `total` = all employees; `page_size=1000` accepted. | `count_documents(query)`, `.sort("emp_code")`, `Query(ge=1)` / `Query(ge=1, le=100)`. |
| 14 | `health` | Returns 200 without talking to MongoDB. | Stop MongoDB: `/health` still says ok. | `ping` command; 503 on `PyMongoError`. |
| 15 | `punch_in` | Unknown employee: `emp` is `None` and `emp["shift_start"]` raises. | `{"emp_code": "EMP0000"}` → **500**. | `get_employee_or_404`. |
| 16 | `punch_in` | `datetime.fromtimestamp(...)` / `datetime.now()` use the **server's local zone**, and `date` is that local date, not the IST date; overnight rule (R1) missing. | On a UTC server, punch at 02:00 IST on the 7th (20:30 UTC on the 6th) → date `…-06`. | `ms_to_dt` (UTC) + `attendance_date` (IST date, overnight rule). |
| 17 | `punch_in` | Check-then-insert race; no unique `(emp_code, date)` index. | 10 parallel identical punch-ins → several 201s and duplicate records. | Unique index `(emp_code, date)`; insert and catch `DuplicateKeyError` → 409. |
| 18 | `PunchInIn` | `punched_at: Optional[int]` is lax: accepts `"1783312500000"` (string), `1.7833125e12` (float) and seconds-looking values like `1783312500`. `status` accepts anything, including `ABSENT` or `"foo"`. | `punched_at: 1783312500` → record dated 1970-01-21; `status: "foo"` → 201. | `EpochMs` = strict int in `[1e11, 4102444800000]`; `status: Literal["PRESENT","WFH","ON_DUTY"]`. |
| 19 | `punch_in`, `list_attendance` | Responses leak the Mongo id as `"id"` and return datetimes instead of epoch ms; `history` times not converted. | Response contains `"id": "66b…"` and `"punch_in": "2026-…"`. | `record_out` builds exactly the contract fields; `dt_to_ms` everywhere incl. `history[].changes`. |
| 20 | `list_attendance` | Loads every matching document into Python, sorts in memory and slices. | On 100k records: slow, high memory; explain shows COLLSCAN. | `find(query).sort([("date",-1),("emp_code",1)]).skip().limit()` backed by an index; `count_documents` for `total`. |
| 21 | `list_attendance` | Sort has no `emp_code` tie-break (contract: date desc, then emp_code asc), so page contents are unstable for equal dates. | Two records on the same date come back in arbitrary order across pages. | Sort on both keys. |
| 22 | `list_attendance` | No validation: `date_from > date_to`, malformed dates, unknown `status`, `page=0`, `page_size=1000`. | `?page=0` returns a strange negative slice; `?status=NOPE` → 200. | `parse_date`, `Status` literal, page bounds; `date_from > date_to` → 422. |
| 23 | Startup | No indexes are created, though the grader's DB has only `_id`. | Every list/analytics query is a COLLSCAN; uniqueness is never enforced. | `ensure_indexes()` in the lifespan hook (idempotent; retried from `/health` if Mongo was not up yet). |

## Looked at and decided were fine

- `load_dotenv()`: it does not override variables that are already set, so real environment variables already win. I kept it, but made `override=False` explicit.
- Sync `def` endpoints with sync PyMongo: FastAPI runs them in a thread pool and `MongoClient` is thread-safe with its own connection pool, so there is no need for Motor.
- One module-level `MongoClient`: correct; creating one per request would be the bug.
- `doc.pop("_id", None)` after `insert_one` in `create_employee`: correct idea (`insert_one` mutates the dict); I replaced it with an explicit `employee_out` so only contract fields are returned.
- The overall shape of the helpers (pure functions taking a datetime and a shift string): good for testing, so I kept the idea but rewrote them around an explicit attendance `day`.
